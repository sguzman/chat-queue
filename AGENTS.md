# Chat Queue development protocol

- Work directly on `main`; this standalone repo is independent of Jobflick Bridge and Chat Signals. No PRs unless explicitly requested. Do not modify either other repository to conceal queue defects.
- Firefox Developer Edition is the only target for implementation acceptance and automated browser QA. A Node fixture or Chromium smoke is not sufficient. Prefer disposable Firefox QA profiles; never touch the user's active browser profile, browser preferences or running tabs automatically.
- Read `ROADMAP.md`, `docs/ARCHITECTURE.md`, `docs/SECURITY.md`, `docs/QA.md`, `docs/PROVENANCE.md` and `API.md` before substantial changes. The task-level canonical `progress.json` drives roadmap generation; run `npm run roadmap` when it changes and `npm run check` before pushing.
- Keep statuses distinct: `planned` (not implemented), `implemented` (source exists but acceptance pending), `verified` (bounded acceptance evidence listed). Percentage = verified atomic tasks / all tasks; do not confuse local tests with live Firefox acceptance. Report percentages for touched workstreams; omit 100% completed milestones from ordinary progress reports.
- Emoji tags belong at milestone, phase, feature and task levels. No project color or GitHub swatch needed unless expressly requested.
- Chat Signals owns response-state inference. The current DOM root attribute is provisional and spoofable by page scripts; production queue execution requires a versioned authenticated signal with current conversation identity and response epoch. No guessing from vanished Stop, old Copy, title emoji, HTTP completion or elapsed time.
- An uncertain Send is never retried automatically; manual cancel, failure, route change or extension/browser reload must never silently resume queue dispatch. Preserve occupied drafts and existing attachments. Do not perform high-frequency transcript scraping, background tab enumeration, network interception or arbitrary page reloads.
- External extension API must check exact caller identity and narrowly scoped permissions. Prompt content is private browser storage and must not leak to other sites, debug logs or unknown extensions. Avoid per-page global JS API that can be invoked by the host website.
- The HUD uses theme modes `System` (default), `Light`, `Dark`, CSS variables and Shadow DOM isolation. Use accessible controls, comfortable margins, keyboard equivalents to drag, reduced motion and Atkinson Hyperlegible preference with system fallback.
- Public source/docs/issues/commits/actions must be sanitized. Do not print or commit private chat contents, personal messages, screenshots, cookies, tokens, local paths, accounts, credentials or venting language.
- QA should be executed by automation, not offloaded to the user except unavoidable one-time setup. Fail a milestone gate on missing evidence, even when implementation appears convincing.
