# 🛡️ Production security audit

Chat Queue runs `node scripts/security-audit.mjs` inside `npm run check` on every commit to `main`. The policy checks **the extension distributed to Firefox**, not tests or examples:

- **Permissions and script contexts:** storage-only permission; exactly one `https://chatgpt.com/*` content-script match, fixed isolated-world entrypoints at `document_idle`, fixed Firefox background script list and no unreviewed manifest execution keys such as `world:"MAIN"` or extra workers. No optional hosts or `externally_connectable` declaration. The only web-accessible assets are the audited isolated editor files, `ui/draft.html` and `ui/draft.js`, restricted to `https://chatgpt.com/*`.
- **Identity and disclosure:** the stable Firefox add-on ID and Mozilla `data_collection_permissions.required=["none"]`. Unknown Gecko update URLs, optional collection categories or additional disclosure keys are rejected and require deliberate review.
- **Assets and execution:** local Options scripts, no remotely sourced UI assets, remote CSS URLs, form destinations, inline event-handler attributes, dynamic `eval` / `Function` or dynamic module imports.
- **Network:** production JavaScript cannot introduce `fetch`, `XMLHttpRequest`, `WebSocket`, or `sendBeacon` without the audit failing. The only permitted URL literal in production scripts is the ChatGPT origin guard.
- **Dependencies:** the package is private and has no runtime dependencies or dependency-install declaration. CI installs explicitly pinned, QA-only tools separately.

**Isolated private editor:** `scripts/security-audit.mjs` also enforces a strict HTML tag allowlist and the single exact `draft.js` script for `ui/draft.html`. Extra resource-bearing tags, unreviewed scripts, CSS `url(...)`/`image-set(...)`/`@import`, protocol-relative resource URLs, meta refresh, inline event handlers and form targets are rejected. `tests/security-audit.test.js` mutates disposable copies with malicious resources and event handlers; none are added to the packaged extension. This source-level control complements, but does not replace, Firefox CSP and an independent review of the actual editor messaging boundary.\n\n`tests/security-audit.test.js` copies the public extension source into disposable directories and verifies that permission escalation, unreviewed content-script worlds/entrypoints/background workers, network code, remote Options scripts/CSS/form actions and unreviewed local Options scripts are all rejected. These intentionally bad fixtures are never shipped in the production extension.

**Limits:** this is a conservative source-level check, not an independent review of all JavaScript behavior, CSP enforcement, data exfiltration through ChatGPT's own composer, storage corruption, library provenance, extension impersonation, or browser bugs. The live ChatGPT site, real Chat Signals publisher, cross-extension authorization changes, and authenticated Send remain separate adversarial acceptance gates. A malicious or compromised already-authorized extension is outside the static audit's guarantee. The audit itself can be bypassed by changes to its code or to CI; such edits require review.

Do not represent a passing source audit as Mozilla signing, full privacy validation, or permission to run unattended sends in a personal Firefox profile.

## CI action dependency integrity

All third-party GitHub Actions in the three reviewed workflows (`.github/workflows/check.yml`, `.github/workflows/qa-launcher.yml`, and `.github/workflows/codeql.yml`) are pinned to immutable **40-character Git commit SHAs**. `scripts/ci-supply-chain-audit.mjs`, enforced by `npm run check`, audits the exact workflow inventory, action owners and SHAs, and permission scopes; it rejects mutable tags, unreviewed workflows/owners and `pull_request_target`. General checks and the launcher use read-only `contents`; only CodeQL has separately audited `security-events: write` and `actions: read` for findings publishing and analysis. Adversarial workflow-mutation tests verify these boundaries.

## Independent static-analysis gate

The separately maintained, immutable-SHA-pinned CodeQL action scans the repository's JavaScript with `security-extended` queries on `main`. `scripts/codeql-findings-gate.mjs` requires a well-formed CodeQL SARIF file and rejects missing reports, symlinks and **any reported finding**, rather than treating a successful analysis step as proof of zero findings. It opens the SARIF once with `O_NOFOLLOW` and inspects that file descriptor; bounded SARIF artifacts are retained for independent inspection. The gate previously exposed and fixed a missing origin check in a localhost-only QA fixture and a filesystem race in its own SARIF reader. This is automated third-party static analysis, **not** a human penetration test or authenticated site/privacy qualification.

## Signed-package source isolation

The optional Mozilla unlisted-signing script remains blocked until 95 pre-tag acceptance tasks pass. After that gate it stages only explicitly allowlisted extension files. Source-directory symlinks are rejected; source files are opened with `O_NOFOLLOW`, checked by descriptor and copied from the same descriptor into a private, new staging file. Disposable regression tests prove an allowlisted filename symlink and a symlinked `src` directory both stop **before** simulated lint/sign, without uploading source or contacting Mozilla. This does not claim an XPI has been signed or accepted.

Pinning source commits prevents tag movement from silently changing executed CI steps. It does **not** independently audit the pinned upstream code, Ubuntu runner images, npm registry tarballs, the Firefox binary, system packages, or AMO signing infrastructure. Upgrades must deliberately update and review the pinned commit and audit policy; the static audit must not treat a new repo or tag as trusted solely because it parses.
